================================================
  Oil / Water Gauge — 2.42" SSD1309 (128x64) テスト用
  ビルド 2026-11-13 / PlatformIO atmelavr + U8g2 2.36.18
================================================

■ これは何
本番パネル（ZJY270S0700XG31 = SSD1322 256x64）とは別に、
2.42インチ 7pin SPI モジュール（IC = SSD1309、128x64）で動くビルドです。
実機で「数値が出ない」症状が出たときの切り分け用。

■ 配線（Nano ← パネル）
  GND  → GND
  VCC  → 5V（モジュールにレギュレータがあるので 3.3V でも可）
  SCK  → D5
  SDA  → D3
  RES  → D6
  DC   → D4
  CS   → D9
※ アナログは従来どおり A0=油温 / A1=油圧 / A2=水温

■ 書き込み手順
1. このフォルダ（OilWaterGauge-Windows）をドキュメントなどへ置く
2. HOWTO_PowerShell_Paste.txt の「==== ここからコピー ====」の中身を
   Windows PowerShell に貼り付けて Enter
   ※ 貼り付け先のパスを、実際に置いたフォルダに変えること
3. 開いたページで「書き込む（Old Bootloader）」
   失敗したら「New Bootloader」
   （HEX は両方同じ内容なので、書き込み方式だけの違いです）

■ 画面
  起動時    : Oil / Water + 「SSD1309 128x64」
  通常表示  : 3分割（WATER / OILT / OILP）
              数値は logisoso18、単位は数値の下の行
  更新      : 水温・油温 2秒 / 油圧 0.5秒

■ A版 / B版
  A : 列オフセット 0（通常）
  B : 列オフセット 2（画像が右に2pxずれる固体向け）
  まずAを焼き、砂嵐が残る／ずれる場合だけBを焼いてください。

■ 前版で砂嵐が出た原因
  最初のビルドは SSD1309 のフルバッファ（1024B）を使っていたため、
  Nano のRAM 2048B のうち 79% を消費し、スタックが表示バッファを壊していた。
  現在は本番機と同じページバッファ（128B / RAM 39%）に変更済み。
  これで砂嵐が消えれば、原因はRAMで確定。

■ 症状が出たときの見かた
・数値だけ出ない（ラベルと単位は出る） → 印刷経路（Print::printFloat）の問題
・画面が砂嵐／点が出る               → まずB版を試す。両方だめなら配線（CS/DC/RES）
・何も出ない                         → 配線（特に DC/RES）か初期化
・数値が「nan」「ovf」               → センサー入力（A0/A1/A2）か Vcc 測定

■ シリアル（115200）
  W=..C(..V) OilT=..C(..V) OilP=..kg(..V) Vcc=..V raw=..
  Vcc は内蔵バンドギャップで実測した AVCC。3.7V 付近なら USB 給電の電圧降下。

■ メモ
・SSD1309 128x64 の U8g2 ドライバはフルバッファ専用（1024B）。
  Nano の RAM 2KB に収めるため Serial のバッファを縮小している。
・ソース側は platformio.ini の env:nanoatmega328_ssd1309
  （-DDISPLAY_SSD1309_128X64=1）で同じものがビルドできる。
