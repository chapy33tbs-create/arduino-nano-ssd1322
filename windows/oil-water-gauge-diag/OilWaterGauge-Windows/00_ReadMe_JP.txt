================================================
  Oil / Water Gauge — 診断ビルド（1回だけ焼く用）
  SSD1322 / ZJY270S0700XG31 / 256x64 専用
  2026-11-13 ビルド / RAM 49.9% (1021B) Flash 67.3% (20670B)
================================================

■ これは何
本番パネル（SSD1322 256x64）で「ラベルと単位は出るのに数値だけ出ない」
現象の原因を、1回の書き込みで確定させるための診断ファームです。
画面は 3 秒ごとに 3 画面を自動で切り替えます（1/3 → 2/3 → 3/3）。

■ 書き込み
1. このフォルダをドキュメントなどへ置く
2. HOWTO_PowerShell_Paste.txt の「==== ここからコピー ====」の中身を
   PowerShell に貼り付け、Enter（パスは実際の場所に変える）
3. 開いたページで「書き込む（Old Bootloader）」
   失敗したら「New Bootloader」

■ 3画面の意味

 [1/3 MAP]  画面の形とフォントの点検
   ・四角い枠（4辺とも出るか）
   ・左端に 8px ごとの目盛り
   ・最下行（y=62〜63）に白い帯
   ・大きく「0123456789」（logisoso24）
   ・小さく「nan inf kg/cm2」
   ・左上に「Vcc=4.95 free=521」＝実測電源電圧と空きRAM

 [2/3 PATH]  同じ数字を3つの描き方で比較（値は固定 12.3）
   左 print … 本番と同じ u8g2.print(12.3, 1)（小数の自動書式）
   中 str   … 文字列そのまま u8g2.print("12.3")
   右 draw  … u8g2.drawStr("12.3")

 [3/3 LIVE]  実測値
   上段 小フォント: W=水温 T=油温 P=油圧
   中段 小フォント: raw 生ADC値3つ
   下段 大フォント: 水温の数字だけを logisoso24 で再描画

■ 判定（写真を見れば確定します）

 A. 1/3 の「0123456789」が出る
    → フォントと下半分の描画は正常。「数値だけ出ない」は
      本番レイアウト固有（y=52 のベースライン）か、値が nan/inf。

 B. 1/3 の枠の下辺・下の白帯が出ない／目盛りが途中で切れる
    → 縦方向のマッピングずれ（ZJYリマップ）。表示可能領域が
      64行より狭いので、y=52 の数値だけ画面外に落ちていた。

 C. 2/3 の print だけ空で、str と draw は出る
    → Print::printFloat 経路の問題。値の文字列化を snprintf に
      差し替えれば解決（恒久対策）。

 D. 2/3 が3つとも空
    → 大きく描くこと自体が失敗。logisoso24 のグリフ欠け、
      またはページバッファ経路の問題。フォントを helvB12 に
      落とすか、数値を drawStr + snprintf にすれば回避できる。

 E. 3/3 の下段（大フォント）だけ空で、上段の小フォントは出る
    → 同じ値がフォント依存で消える = logisoso24 のグリフ欠け確定。

■ 記録しておくと良いもの
 ・3画面それぞれの写真（ピント優先）
 ・シリアルの1行（115200）:
   W=..C(..V) OilT=..C(..V) OilP=..kg(..V) Vcc=..V raw=..,..,.. free=... scr=N
   → 数字が画面に出ていなくても、シリアルには値が出ます。
     シリアルに値が出ていれば演算は正常＝描画だけの問題と確定。

■ 注意
・このビルドは SSD1322 専用です。SSD1309(128x64) を繋ぐと砂嵐になります。
・本番ビルド（env:nanoatmega328）は診断コードの影響を受けません
  （バイナリ 20,070B / sha256 4806d300… で従来と完全一致を確認済み）。
